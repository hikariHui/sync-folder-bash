运行项目集成测试，步骤如下：

1. 先确认 release 二进制存在，不存在则先编译：
   ```
   cargo build --release
   ```

2. 运行测试脚本：
   ```
   bash test.sh
   ```

3. 解读结果：
   - 每行 PASS/FAIL 对应一个断言
   - 末尾汇总显示通过数/总数
   - 若有 FAIL，输出中会包含具体失败原因（期望值 vs 实际值）
   - 脚本返回非零退出码表示有失败

## 测试覆盖场景

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 基础新增 | A 有文件 B 为空，文件被正确复制，大小一致 |
| 2 | 跳过已同步 | 路径+大小相同的文件不被重复写入（mtime 不变） |
| 3 | 文件更新 | 同路径但大小不同时，B 更新为新版本，旧版本进 trash |
| 4 | 移动识别 | 文件在 B 中换目录后被识别为内部移动，不触发跨盘复制 |
| 5 | 多余文件清理 | B 中 A 没有的文件移入 `_trash_*/` |
| 6 | 移动歧义 | B 中多个同名同大小文件时贪心匹配，一个移动一个 trash |
| 7 | 递归子目录 | 深层嵌套路径正确处理 |
| 8 | 幂等性 | 二次运行显示"已完全同步"，无多余操作 |
| 9 | trash 隔离 | `_trash_*` 历史目录不参与扫描，不触发额外操作 |
| 10 | 错误处理 | 路径不存在、A=B、无参数等情况均正确报错退出 |
